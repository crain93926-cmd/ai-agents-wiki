工具：讓模型能動手

工具是 agent 能呼叫的外部功能，用來查資料、執行程式或操作其他系統。

語言模型本身只會產生文字。工具就像交給助理的電話、計算機和門禁卡：有了它們，助理才能真的去查、去算、去辦事。

為什麼需要工具

模型學到的知識停在訓練的那一刻，也不能自己執行程式或讀你的私人資料。透過呼叫外部的 API（應用程式介面），agent 可以取得模型本身沒有的東西：最新的資訊、執行程式碼的能力、專有的資料來源。Weng 2023

三種工具

  • 資料類：取得資訊，例如查資料庫、讀文件、搜尋網路。
  • 行動類：改變外部系統的狀態，例如寄訊息、更新紀錄、把案件轉給真人。
  • 協調類：把另一個 agent 當成工具來呼叫。

這個分類出自 OpenAI 2025。行動類工具會真的改變東西，風險比資料類高，要搭配護欄。

工具的說明要寫給模型看

模型是靠工具的名稱與說明文字來決定要不要用、怎麼用。所以設計工具時，要像寫給新進同事的說明一樣：講清楚用途、給範例、說明邊界情況，並且實際測試模型會怎麼用錯。這個「agent 與電腦之間的介面」值得花和寫提示一樣多的心力。Anthropic 2024

讓工具不容易被用錯

好的做法是直接把容易出錯的用法擋掉。一個實例：某個工具改成只接受絕對路徑之後，模型用相對路徑造成的錯誤就消失了。Anthropic 2024

工具怎麼接上來

每個工具都需要名稱、說明和輸入格式，AI 應用才能把它交給模型使用。MCP：工具的共通插頭 把這件事標準化：應用程式先向提供工具的程式查詢清單，再依模型的決定去呼叫。MCP 文件
